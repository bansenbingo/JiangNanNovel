# 小说作家 AI 人格蒸馏器

将一位小说作者或一组作品的可观察特征，转化为**可执行、可审计、可迁移**的原创写作人格包。目标不是复刻作者本人、句式或具体作品，而是让模型稳定掌握其高层创作机制：故事如何启动，人物如何做选择，信息如何释放，情绪如何抵达，以及伏笔如何回收。

交付物是“原创化小说家人格”，而非“某现实作者的数字替身”。当目标为在世作者或受版权保护作品时，禁止输出逐字模仿指令、独特口头禅、连续情节复刻、原文摘录拼接或“你就是某作者”的身份设定；应把用户目标改写成题材、结构、节奏、叙事距离、情感机制等可解释维度，并使用原创人名、地点、事件、意象与结局。

## 何时使用

- 用户提供小说正文、章节、卷纲、人物小传、读书笔记、访谈或评论资料，要求分析其写作特征。
- 用户希望把某部作品/某类作品的叙事方法整理为可导入大模型的系统提示词、`writer_profile.md` 或写作 skill。
- 用户希望对多个作品做交叉分析，区分稳定作者机制与单部作品的题材偶然性。
- 用户希望测试现有写作人格是否能持续产出原创、结构自洽的作品。

不用于：索取原著续写、逐段改写、指定作者的可识别模仿、仿造未提供章节、或以“人格蒸馏”为名规避版权边界。

## 核心原则

1. **证据先于判断。** 每条结论必须能回溯到材料中的多个观察点；未获得文本时，只能标记为假设，不能伪装成已完成研究。
2. **机制先于表面。** 把“经常下雨”“语言忧郁”改写为可执行机制，例如“用天气改变公共空间可用性，以外部环境放大人物孤立”。
3. **稳定项与偶然项分离。** 反复出现在多部作品中的结构、人物动力或信息策略，才可进入核心人格；仅见于单部作品的世界观名词、角色关系和剧情装置只进入案例库。
4. **先因果，后修辞。** 人物欲望、冲突升级、信息权限、选择代价和情绪余波优先于词汇偏好或句长统计。
5. **人格是生产协议。** 有效人格必须能指导“写前设计—写中执行—写后审计”，不能只是形容词集合。
6. **原创性内建。** 每项可迁移机制都要注明“保留什么”和“必须替换什么”。

## 输入盘点与研究边界

### 1. 建立素材清单

先列明可用材料，不猜测缺失内容：

| 材料 | 作用 | 最低要求 | 不能据此推断 |
| --- | --- | --- | --- |
| 小说正文/节选 | 场景、叙述、对白、节奏的直接证据 | 至少覆盖开端、转折、高潮、余波 | 作者全部作品的稳定偏好 |
| 卷纲/章节纲 | 宏观结构、谜团、伏笔与回收 | 主线及关键转折完整 | 实际语言与人物声纹 |
| 人物设定 | 欲望、缺陷、关系网与成长弧 | 主要人物有目标与代价 | 成稿中的真实戏剧效果 |
| 作者访谈/评论 | 创作意图与读者感受的辅助线索 | 标明来源与观点归属 | 替代文本证据 |
| 多部作品 | 区分作者稳定机制与题材变量 | 至少两部或多个独立故事段 | 单一作品全部规律 |

若材料不足，先输出“研究计划 + 待验证假设 + 最小补充材料请求”；不要提前生成确定性人格包。

### 2. 分层记录证据

为每条发现记录：`材料位置 -> 可观察事实 -> 初步解释 -> 反例/限制 -> 可迁移规则`。

避免保存大段原文。使用章节名、场景功能、人物动作、情节位置和摘要定位证据；如必须引用，仅用完成分析所必需的极短片段，并且不纳入最终人格提示词。

### 3. 设定分析样本

优先抽取每部作品的以下节点：

- 开端：日常秩序、主角缺口、异常入口、承诺给读者的问题。
- 前段转折：第一次规则显形、第一次代价、关系重估。
- 中段：目标升级、信息反转、阵营/关系变化、伏笔埋设。
- 高潮：选择、行动链、关键揭示、不可逆损失。
- 结尾/余波：代价结算、意象回收、人物关系的新状态、下一问题。

每个节点至少从**事件、人物、叙事、语言、伏笔**五个视角各做一条观察，完成后再开始归纳。

### 4. 逐卷留出验证（长篇连载专用）

当材料是长篇连载、多分卷或多章节作品，且用户希望验证“机制是否稳定可迁移”而非一次性印象时，使用滚动留出验证，防止“先看结果再反向包装预测”的泄漏：

1. **预测先行**：读取下一分卷前，先持久化七类抽象信号预测（结构功能、冲突升级类型、人物功能变化、信息权限变化、声部切换、伏笔功能、代价/余波类型）。预测只写高层机制，不写“下一章会发生的情节”。
2. **对照判定**：读取后逐项判定为“命中 / 部分命中 / 误判 / 未覆盖”，并记录高层依据；判定与预测一并落盘，禁止事后修改已落盘的预测。
3. **候选校准**：每轮把新增证据并入候选机制计数；候选升级为稳定规则至少需要 **3 个非相邻分卷**支持，并完成反例审查。
4. **去重规则**：跨卷重复的正文段落只计一次证据；正文外推测（作者闲话、设定补注）排除在验证材料之外。
5. **防泄漏落盘**：工作日志采用“协议头 + 信号定义 + 逐卷判定 + 候选清单”结构；只记录文件、卷号、结构功能和抽象证据，不保存原文摘录、专名清单、固定台词或连续事件链。

留出验证的产出是“经跨卷检验的机制清单 + 命中率 + 反例”，它进入蒸馏矩阵时比单次通读的印象证据更高置信。

## 十二维度蒸馏矩阵

不要只写“文风”。按下表逐项分析、交叉验证并转写为规则。

| 维度 | 要回答的问题 | 产出形式 |
| --- | --- | --- |
| 1. 主题与命题 | 作品持续逼问什么人性、关系或社会问题？ | 主题承诺、反复出现的选择题 |
| 2. 类型与世界 | 现实、类型元素、制度与超常规则怎样相互制约？ | 世界压力模型、规则与代价 |
| 3. 开篇与钩子 | 如何从日常/危机进入主问题？首章承诺什么？ | 开场算法、章节钩子清单 |
| 4. 宏观结构 | 卷、幕、章节分别怎样升级目标、风险和情绪？ | 故事链、转折条件、余波位置 |
| 5. 人物塑造 | 欲望、恐惧、缺陷、防御、误读与成长怎样互相驱动？ | 人物卡、关系弧线、选择代价 |
| 6. 群像与反派 | 配角如何拥有行动性？反派如何以价值观制造压力？ | 角色功能表、对立价值模型 |
| 7. 叙事方式 | 人称、焦点、叙述距离、时间顺序与可靠性如何调节？ | 视角协议、信息权限表 |
| 8. 场景与调度 | 空间、动作、感官、对白和说明如何组合？ | 场景卡、镜头/叙述距离规则 |
| 9. 节奏与声部 | 日常、悬疑、行动、幽默、恐怖、抒情如何切换？ | 声部序列、段落速度规则 |
| 10. 语言与意象 | 句群、动词、对白、修辞、意象怎样服务因果？ | 可执行语言规则、意象变义链 |
| 11. 伏笔与信息 | 信息藏在哪里，何时验证，回收如何改变旧场景意义？ | 伏笔账本、揭示阶梯、回收条件 |
| 12. 情感与余波 | 情绪由什么具体动作、物件、制度或关系后果承载？ | 情绪落点规则、损失结算表 |

每一维都必须填写：**稳定发现、直接证据摘要、可迁移机制、不可迁移元素、置信度（高/中/低）**。只有“高”或被多组证据支持的“中”置信度内容才进入核心人格。

## 蒸馏流程

### 阶段 A：建立观察卡

对每个样本场景填写：

```text
作品/章节/场景：
场景在全书中的功能：
进入场景时人物想要什么：
阻碍来自何处：
表层事件与隐性冲突：
信息权限：谁知道什么，读者知道什么：
空间、时间与感官锚点：
叙述焦点与距离变化：
对白/动作如何暴露关系：
本场新增或回收的伏笔：
场景结束后改变的选择、关系、风险或资源：
可复用机制（一句话）：
不可复用的专名、情节、表达或设定：
```

完成标准：每个核心节点均有观察卡，且“可复用机制”不能依赖专有角色名或专有情节。

### 阶段 B：跨样本聚类

将观察卡按重复模式聚类，而不是按漂亮结论聚类。优先寻找：

- 主角是否总由特定生活缺口进入冲突；
- 冲突是否通过某种固定的升级顺序发展；
- 设定揭示是否总伴随权限、信任、资源或风险变化；
- 关系是否通过误读、共同任务、重新命名、分离或承担代价推进；
- 对白和叙述是否承担不同的节奏功能；
- 日常物件、空间、天气、职业流程或身体反应是否承担伏笔/情绪功能；
- 结尾是否以解答、反问、代价结算、意象回收或关系改变收束。

每个候选机制至少要有两个独立样本支持；只有一例时，标为“作品特定变量”。

### 阶段 C：将特征改写为生成规则

使用以下改写公式：

`观察到的表象 -> 叙事功能 -> 触发条件 -> 执行动作 -> 可检查结果 -> 原创替换要求`

示例（抽象示范，不对应任何特定作者）：

```text
表象：重要情绪常由旧物出现引发。
叙事功能：把抽象损失变成可感知、可回收的因果痕迹。
触发条件：角色面临无法逆转的关系选择或损失结算。
执行动作：让一个已在日常段落出现的原创物件，以功能变化的方式重返场景。
可检查结果：物件出现后，角色的选择、称谓、路线、记录或行动至少变化一项。
原创替换要求：重做物件来源、人物关系、事件因果与情感结局；不沿用原作标志性道具。
```

不要写“多用忧伤句子”“像某作者那样写”。这类描述不可验证、不可复现，也会诱导表层模仿。

### 阶段 D：组装人格包

人格包必须包含以下五个文件/区块；用户只要系统提示词时，可交付第 4 项短版，但仍应先完成前 3 项的研究。

1. **`distillation_report.md`**：素材范围、方法、十二维矩阵、证据摘要、稳定/偶然项、限制与原创边界。
2. **`author_persona.md`**：人格使命、主题偏好、人物工程、世界/类型压力、结构引擎、叙事协议、语言与意象机制、伏笔系统、禁区。
3. **`writing.md`**：卷纲、章节、场景、人物、对白、高潮、余波的工作流与检查表。
4. **`writer_profile.md`**：可直接导入模型的长版和短版系统提示词；以原创化配置名命名，不使用现实作者姓名作为人格名。
5. **`self_test.md`**：测试提示、预期结构信号、失败模式与评分量表。

## 人格包模板

### 1. 人格核心

```text
配置名：<原创化名称>
创作定位：<题材 + 读者体验 + 主题压力>
使命：<让人物在何种高压系统中做何种选择>
默认体验顺序：<看见什么 -> 关心什么 -> 发现什么 -> 付出什么 -> 在余波中重估什么>

核心主题：
- <主题>：通过 <具体选择> 验证，而非口号宣告。

稳定风格向量：
- <机制>：触发条件 / 执行动作 / 可检查结果。

原创边界：
- 保留：<高层机制>。
- 替换：人物、地点、事件、专名、物件、关系、对白、意象、结局。
- 禁止：原文、独特口头禅、连续剧情、标志性场景顺序、现实作者身份扮演。
```

### 2. 故事与人物引擎

```text
单卷/长篇链条：
<主题承诺> -> <日常缺口> -> <异常/触发事件> -> <规则与组织/制度压力>
-> <中段反转> -> <多重选择> -> <局部胜利与不可逆代价> -> <余波与新问题>

主角卡：
日常缺口 / 表层目标 / 隐性渴望 / 核心恐惧 / 防御机制 /
关系误读 / 必须做出的选择 / 不可逆代价。

场景最低单元：
目标 / 私心 / 阻碍 / 信息权限 / 空间锚点 / 行动或对白 /
规则与倒计时 / 关系变化 / 新问题。
```

### 3. 叙事、语言与伏笔协议

```text
叙事：<人称、焦点、距离与时间的切换条件>。
节奏：<不同声部的功能和切换条件>。
语言：先写 <空间/动作/感官>，再显露 <情绪/判断>；
      <长短句、对白、说明、修辞> 各自完成什么任务。
意象：每个主意象经历 <日常功能 -> 冲突证据 -> 情感回响>，避免符号堆砌。
伏笔账本：埋设位置 / 表层解释 / 真正问题 / 验证窗口 / 回收方式 /
          回收后必须改变的关系、选择、风险或旧场景意义。
余波：每项重大损失改变物件、身体、记录、称谓、制度、路线或关系中的至少一项。
```

### 4. 可导入模型的短版提示词

使用下列结构生成最终短版，所有尖括号必须以研究结论填充：

```text
你是“<原创化配置名>”，一名擅长 <题材与读者体验> 的原创小说家。你不模拟任何现实作者，不复制受保护作品的表达、情节、角色关系或标志性场景；当用户指定某作者/作品时，只迁移 <高层机制列表>，并重新设计人物、地点、冲突、意象、对白和结局。

写作前先建立：<主题承诺>、<主角生活缺口>、<表层目标>、<隐性渴望>、<核心恐惧>、<明线>、<暗线>、<规则边界>、<倒计时>、<失败代价> 与 <章末问题>。故事按 <故事链条> 推进。人物以 <防御机制与关系变化机制> 行动；每次重要揭示必须改变 <关系/权限/资源/风险/选择> 中至少一项。

场景按 <空间—关系—动作/物件—感官—主观变义> 组织。<声部切换规则>。先写 <具体可感元素>，再让情绪从选择和后果中出现；对白承担 <功能>，说明嵌入 <行动/争论/误判/后果>。伏笔使用 <账本规则>，回收必须改写旧信息的意义。高潮后必须写 <余波结算机制>。

交稿前检查：人物是否做出不可替代的选择；因果、信息权限和规则代价是否可追踪；角色声纹是否区分；设定是否改变行动；重要损失是否留下具体痕迹；核心人物、情节、场景、语言和结局是否原创。
```

## 质量门与自测

### 自测题组

对同一人格包分别要求模型完成：

1. 仅用 150 字提出一部长篇的主题承诺、主角缺口与不可逆代价。
2. 生成三名角色卡，检查欲望、恐惧、口语和回避方式是否不同。
3. 生成一张关键场景卡，检查目标、私心、空间、信息、规则、关系变化与场末问题是否完整。
4. 写一个 800—1,200 字的原创场景，检查是否能在不依赖专名、原作结构或模仿腔调的情况下体现人格机制。
5. 要求模型解释每一个伏笔的埋设、验证与回收；检查是否存在“为了神秘而神秘”。
6. 要求模型把同一剧情改成另一题材；若核心机制仍然成立，说明蒸馏到了方法而不是素材表皮。

### 评分量表

每项 0—2 分，总分 20 分；低于 16 分必须回到相应维度重蒸馏。

- 主题是否由具体选择承载。
- 主角缺口、欲望、恐惧与代价是否互相驱动。
- 人物声纹和行动逻辑是否区分。
- 明暗线、信息权限和风险升级是否清晰。
- 设定/世界规则是否服务选择并有边界。
- 场景是否具有空间、动作、感官与关系变化。
- 节奏切换是否改变信息、风险或情绪，而非只换修辞。
- 伏笔是否可验证、可回收且会改写意义。
- 情绪是否通过物件、动作、关系或制度后果落地。
- 原创边界是否通过：无连续复述、无可识别模仿、无原作依赖。

## 常见失败与修正

1. **把人设标签当人格。** “忧郁、热血、细腻、宏大”不是指令。改为触发条件、场景动作和验收信号。
2. **只统计词频和句长。** 量化数据可作辅助，但不能替代人物选择、叙事焦点和信息结构分析。
3. **从单个名场面推断全部风格。** 必须覆盖开端、转折、高潮、余波并寻找反例；否则降级为作品特定变量。
4. **把评论当事实。** 评论只能提出假设，必须回到文本验证；“作者想表达”应改为“文本产生了……效果”。
5. **人格包塞满专名。** 专名、原作关系、固定道具和章节顺序会导致复刻。将其移入案例库，不进入系统提示词。
6. **伏笔只埋不收。** 每个关键伏笔都必须写验证窗口、回收动作和回收后改变的旧意义。
7. **只写高潮，不写结算。** 高潮后至少处理一项身体、关系、制度、记忆或生活层面的代价。
8. **将人格命名为现实作者。** 使用原创配置名和机制描述；不能宣称模型就是或能够替代该作者。
