# Novel Source Compressor

这是续写/改写技能组的原文压缩层。目标不是写一篇书评，也不是把每章缩成一句空泛摘要，而是把“后续写作必须知道的故事状态”从大量正文中抽出来。可以把它理解为：修辞有损压缩，因果和连续性尽量无损压缩。

运行要求：需要文本读取、文件遍历和必要时的编码/章节定位能力；不要求外部网络或专用数据库。

## 1. 选择工作模式

从用户目标和现有材料选择一个主模式，并在输出开头声明：

- `handoff-compress`：原文压缩后交给 `novel-continuation-outline` 做续写/改写规划。默认输出标准全局大纲，并对末尾存档点深挖。
- `standalone-outline`：没有上一个技能，生成较详细、可独立阅读的全书/卷章/章节大纲。
- `incremental-merge`：已有 `source_outline_state` 或旧大纲，只压缩新增章节并合并版本，不重写整本。
- `archive-dossier`：用户只想了解人物、时间线、伏笔或世界规则，输出针对性档案；仍需保留证据位置。

如果用户同时要求“压缩后继续写”，先完成压缩并交付 `source_outline_state`，再把它作为输入交给 `novel-continuation-outline`。不要在同一份输出里把压缩、续写正文和大纲混成一个不易复用的长文。

## 2. 输入盘点和证据边界

### 2.1 先建立 source manifest

在总结之前记录：文件路径、文件类型/编码、章节或分卷范围、是否可能是重复版本、是否为完整作品、是否有明确的断点。材料很多时先读取目录/标题和文件尾部定位，不假装读过尚未读取的段落。说明本次已读取范围、抽样方式和未知范围。

### 2.2 信息分层

对重要信息使用四类标签：

- `source_fact`：原文直接写出，必要时附章节或文件位置。
- `user_constraint`：用户要求保留、删除、改写或用于非商用同人。
- `inference`：为连接因果而提出，必须说明推断依据。
- `unknown/conflict`：原文没有定论、版本冲突或读取不足，不要擅自补成事实。

既有 IP、同人或改编材料要把原作事实、用户分歧和压缩者推演分栏，并标作非官方衍生。参考作品只能提取高层结构、节奏或关系压力，不复制连续情节、段落和独特表达；商业出版、付费发行或署名混淆需先提示权利边界。

## 3. 压缩不变量：什么不能丢

每个章节或场景至少抽取一次状态变化，而不是只抄事件名。优先级从高到低如下：

1. **因果链**：事件由什么触发，谁做了什么选择，选择造成什么新压力。
2. **人物状态**：欲望、信息、误会、底线、能力/资源、伤势、秘密和关系状态如何变化。
3. **知识差**：读者、视角人物、对手和其他角色分别知道什么；信息何时被揭示或误导。
4. **连续性**：时间、地点、旅行、物件去向、规则条件、组织流程和能力代价。
5. **承诺与回收**：伏笔、债务、约定、伤口、悬念首次出现、施压、回收或被有意放弃的位置。
6. **末尾交接**：最后一个稳定点、未解决线程、当前角色状态、下一步压力和可开写节点。

可以省略或合并：重复环境描写、没有新信息的情绪重复、例行移动、只改变措辞不改变选择的对白。但如果细节决定人物声音、关系转折、谜面或后续因果，就不能以“氛围”名义删除。

## 4. 分层压缩流程

### Phase A：章节级提取

按章节、场景或明显叙事边界切分，不用固定字符数硬切。每个单元输出：入口状态、行动目标、阻力、关键事件、主动选择、信息增量、关系变化、代价、出口状态、伏笔/承诺和来源位置。一个单元没有状态变化时，标记为过渡并准备与相邻单元合并。

### Phase B：局部弧合并

把连续章节按人物目标、地点、任务或冲突分成弧。合并重复事件，保留第一次建立、压力升级和真正改变选择的版本。每条弧要有入口、升级、转折、低谷/代价、出口，并登记它创建和回收的承诺。

### Phase C：全局结构

从局部弧合并出卷/幕/阶段结构，重建故事核心链：

`现实缺口 -> 可欲的日常/承诺 -> 制度或环境压力 -> 核心选择 -> 公共结果 + 私人结果 -> 新状态`

不要把原文中没有的主题、动机或结局强行补齐；缺口写成 `unknown`。完整作品也要检查终局是否真正回收核心承诺，而不是因为文本结束就宣布完成。

### Phase D：续写尾部深挖

`handoff-compress` 默认对最后一个稳定点及其前后必要窗口展开更细的章节/场景卡：谁在何地、身心状态如何、掌握什么信息、手上有什么资源、欠谁什么、下一场至少会承受哪两种压力。不要只写“未完待续”。

### Phase E：忠实度核验

抽样回读关键转折、人物死亡/离场、关系断裂、规则揭示、高潮和末尾节点。每条高风险结论都应能回指来源位置，或明确标记为推演/冲突。若章节之间存在两个版本，保留分叉，不擅自拼成第三个版本。

## 5. 交付格式

按用户需要选择粒度，但完整输出应遵守 `references/compression-schema.md`。顺序通常是：

1. **压缩版本头**：模式、版本、源文件范围、读取状态、压缩目标和置信度。
2. **事实边界**：`source_fact`、`user_constraint`、`inference`、`unknown/conflict`。
3. **一句话故事核心**：主角、欲望/问题、阻力、核心代价和最终状态；若无法确定，保留候选。
4. **全局结构**：卷/幕/阶段的入口、压力、转折、出口与承诺变化。
5. **章节索引/章节卡**：每章至少有状态、选择、信息、关系、代价、伏笔和来源锚点。
6. **人物与关系档案**：以行为和选择描述，不用空泛性格标签。
7. **世界规则、时间线、物件与资源账本**：只保留会约束选择的设定。
8. **伏笔/承诺回收表与未决线程**：状态为 `open | pressured | paid | abandoned | conflicting`。
9. **末尾交接**：最后稳定点、当前状态、下一场候选、不可擅改事实和风险。
10. **压缩质量报告**：已核验范围、未读范围、可能丢失的信息、冲突和建议回读节点。

## 6. 与 novel-continuation-outline 的交接

当上一个技能存在或用户明确说“喂给上一个技能”时，额外输出一个可独立复制的 `source_outline_state`。它至少包含：

```yaml
source_outline_state:
  version: "source-v0.1"
  source_scope: "文件、章节、分卷和读取状态"
  source_status: "complete | unfinished | partial | conflicting"
  mode: "handoff-compress | incremental-merge"
  compression_depth: "quick | standard | deep"
  confidence: "high | medium | low"
  locked_facts: []
  user_constraints: []
  inferred_items: []
  unknowns_and_conflicts: []
  story_engine: {}
  timeline_anchor: {}
  segment_outline: []
  character_states: []
  relationship_deltas: []
  world_rules: []
  continuity_ledger: {}
  open_threads: []
  promises: []
  payoffs: []
  ending_or_last_stable_point: {}
  next_scene_candidates: []
  traceability: []
  compression_risks: []
```

交接给上一个技能时，明确告诉它：哪些字段是锁定事实，哪些只是推演；哪些原文窗口值得回读；续写应从 `ending_or_last_stable_point` 之后开始，而不是重述已压缩的章节。若上一个技能不可用，使用同一结构继续展开为详细独立大纲。

旧版本若使用 `compression_mode`，接收方应把它视为 `mode` 的兼容别名；新输出统一使用 `mode`。

## 7. 增量合并和版本控制

用户提供旧的 `source_outline_state` 与新章节时，只重新读取新增范围及受影响的前后窗口。更新顺序为：事实锚点 -> 时间/地点 -> 人物与关系 -> 规则/资源 -> 承诺/伏笔 -> 全局结构 -> 末尾交接。输出 `change_log`，说明新增、修正、冲突和不再成立的节点，禁止静默覆盖旧版本。

## 8. 默认行为、提问与禁止事项

- 用户只说“压缩”而未指定深度时，采用 `standard`：全局结构 + 章节索引 + 主要人物/关系 + 末尾交接；用户要继续写时自动切换 `handoff-compress`。
- 只有当输出用途、原文范围或版本选择会改变结果时才提问；表层格式用默认值，问题每轮不超过 3 个。
- 长篇材料不得只读开头和结尾就声称完成；必须说明分层读取与抽样核验范围。
- 不把事件清单冒充大纲，不用新编动机填补证据缺口，不以压缩名义复制大段原文。
- 不在压缩任务中直接续写正文；把创作交给上一个大纲技能或用户明确指定的后续技能。
- 只保留能服务因果、人物、连续性和后续选择的细节；细节越多不代表压缩越好。
