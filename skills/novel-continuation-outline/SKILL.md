# Novel Continuation Outline

这是续写/改写技能组的策划入口。它的产物不是漂亮的概念简介，而是一份能约束后续写作、允许人物反写路线、能追踪伏笔和版本变化的故事工程稿。先建立共同理解，再用开放描述捕捉用户脑中的画面、情绪和关系，再锁会改变大纲的变量；信息够用时主动产出版本，不把用户困在无休止的问卷里。

运行要求：仅需文本阅读与文件读取能力；可处理用户粘贴内容、本地 TXT/MD/EPUB 转录或其他可读取的草稿材料。

## 1. 先判定任务模式

从用户语言和材料中选择一个主模式，可组合但必须说明主模式：

- `idea-to-outline`：只有想法、设定、人物卡或几个场面，需要从零搭建故事。
- `continue`：在现有原文、草稿或存档点之后接写。
- `branch-rewrite`：保留部分原作事实，从一个分歧点重走路线。
- `deep-rewrite`：保留题材、人物或主题，重做冲突、结构和结局。
- `repair-expand`：诊断未完成稿、断裂章节或失衡大纲，提出修订方案。
- `hybrid`：用户同时给了原文和新想法；明确哪些是继承、哪些是改动。

在第一次回复开头给出一行“当前理解”：模式、材料状态、计划交付物、尚未锁定的关键变量。上下文已经明确的事项不要再次盘问。

## 2. 读取和整理材料

### 2.1 材料优先级

按以下顺序建立证据层，不要用常识覆盖用户材料：

1. 用户明确锁定的事实、禁区和结局要求。
2. 用户提供的原文、草稿、章节、人物卡、时间线和旧大纲。
3. 原文中可由行为、因果和场景直接验证的事实。
4. 对缺口的推演、补全和主题解释。
5. 仅作为参考的其他作品、类型惯例或风格形容。

对每条重要信息标记 `事实`、`用户指定改动`、`推演` 或 `待确认`。续写时先找“最后一个稳定点”：最近一次明确发生的事件、人物状态、未解决承诺和可用资源。改写时建立“保留 / 删除 / 新增 / 移位”变更表。

### 2.2 大材料处理

材料很长时，不要假装已读完整本。先定位目录、章节标题、末尾段落、人物和专名，再按冲突相关窗口读取；说明已读取范围和仍未知的部分。引用原文时只摘取完成判断所必需的短语，并优先给出章节或文件位置。

如果输入包含 `novel-source-compressor` 生成的 `source_outline_state`，先把它当作压缩证据层读取：锁定其中的 `locked_facts`、`timeline_anchor`、`character_states`、`open_threads` 和 `ending_or_last_stable_point`，不要重新总结已覆盖章节。只有当 `traceability` 或 `compression_risks` 指向高风险缺口时，才回读对应原文窗口；任何从压缩状态推导出的新内容仍标为 `推演`。

### 2.3 参考作品和既有 IP

参考作品用于提取高层机制，例如叙事距离、节奏、关系压力、意象功能和结局温度；不要复制段落、独特比喻或连续情节。既有 IP 的续写、同人或改编要把原作事实、用户分歧设定和本次推演分栏，并把成品标作非官方衍生；不声称是原作者或官方续作。若用途涉及商业出版、付费发行或署名混淆，先提示权利边界，再把方案转为原创化或要求用户确认权利基础。

## 3. 交互协议：每轮只解决高杠杆不确定性

### 3.1 第一轮

材料充分时，不先发长问卷。先输出一页 `理解快照`：

- 当前模式与读者/体量的合理默认值
- 已锁定事实和用户明确想保留的东西
- 现有冲突、人物缺口、未偿还承诺
- 2-5 个最可能的核心分歧点
- 缺失信息按影响分级：会改变主线 / 只影响场景 / 可由默认值处理

然后只问 1-3 个会改变主线的问题。材料极少时可以先问 3 个；若一个问题已经足以决定路线，先问一个。至少有一个问题应允许用户用自己的话描述构思，除非用户已经把该变量说得非常具体。

### 3.2 提问格式：开放邀请 + 可选支架

会改变人物内核、关系走向、结局压力或主题的问题，先给开放邀请，再给选项作为脚手架。选项不是封闭枚举，不能要求用户把复杂想法压成一个字母。每个问题都说明它会改变什么：

> **开放邀请**：你脑海里的结尾画面是什么？不用先想术语，可以说一个场景、一个人留下/离开的状态，或一种你希望读者最后带走的感觉。
>
> **可选支架**：如果你想快速定位，可以参考：A 保住关系但目标失败；B 目标完成但关系不可恢复；C 两者都付出代价；也可以说一个完全不同的版本。
>
> **为什么问**：这会决定中段是否允许牺牲核心关系，以及哪些伏笔必须在高潮前回收。
>
> **临时默认**：你暂时不回答时，我先采用 C，并把它登记为可回滚假设。

用户自由回答后，先用一句话复述其意图，再将回答写入 `vision_capture`，区分用户原话、解释和仍需确认的部分。不要把用户的隐喻强行翻译成固定选项；可以保留“像一盏熄灭后还在发热的灯”这样的意象，并说明它暂时影响了哪个结构变量。

不要询问已经从材料中能可靠推出的答案。用户说“你来定”或暂不回答时，采用推荐默认，并把它登记为可回滚假设，不停住流程。用户一次改动一个关键变量时，重新计算受影响的结构、人物弧、伏笔和篇幅，而不是只替换一句话。

### 3.3 开放问题的覆盖范围

第一轮优先从以下方向选择至少一个开放问题，避免把用户的构思缩成类型标签：

- **画面**：你最想保留的一个瞬间、空间或动作是什么？
- **关系**：如果只能保住一段关系，你希望它在结尾变成什么样？
- **情绪**：读者合上这一卷时，你希望胸口留下哪种感觉？它不必是“悲/喜”二选一。
- **代价**：你觉得这个故事里最不能被轻易抹平的损失是什么？
- **边界**：哪些人物、事实、意象或结局即使大纲更方便也不能动？

用户已经给出明确长段构思时，开放问题改为核对和扩展，不重复让用户描述已有内容。每轮仍控制在 1-3 个问题，并保留“选项支架 + 自由回答”两条入口。

### 3.4 何时进入大纲

当以下五项中至少四项可用时进入 v0.1：核心人物、起点/分歧点、主要欲望或问题、预期终点、规模/体量。缺一项也可以进入，但必须显式写假设和待确认项。每轮交付一个可评审的小版本，邀请用户只指出“保留 / 删除 / 更改 / 暂不决定”，不要要求用户重新描述全文。

## 4. 规划模型

先写一句现实层困境，再写奇观或类型机制。每条支线都必须回答：它迫使谁做了什么选择、改变了哪段关系、在哪个节点收口。

### 4.1 因果核心

锁定以下链条：

`现实缺口 -> 可欲的日常或承诺 -> 制度/环境压力 -> 核心选择 -> 公共结果与私人结果 -> 新的不可逆状态`

如果只有谜团、升级或反转，没有人物必须失去或承担的东西，先补关系代价，不急着扩展世界观。

### 4.2 人物弧

每个主要人物至少记录：当前状态、想要、真正需要、错误信念、底线、可用资源、关键关系、压力下的默认反应、被迫改变的事件、最终选择、选择后的代价。不要用形容词代替行为；“冷漠”要落到隐瞒、延迟、拒绝或保护等可观察动作。

人物动机跨场景稳定时，允许它反写原先路线，但同时重锁核心冲突、结局压力、篇幅和未决问题。人物不能只在高潮突然改变性格来拯救大纲。

### 4.3 结构尺度

按用户需求选择尺度，不强行填满全部层级：

- **全书/季/卷**：主题问题、起点、转折、低谷、高潮、结局和各卷收口。
- **章节**：每章的目的、视角、入口状态、行动目标、阻力、转折、出口状态、关系变化、信息揭示和代价。
- **场景**：时间地点、在场者、谁掌握什么信息、动作/对话推进、不可逆变化和下一场的压力。

每个节点都写“进入状态 -> 做出选择 -> 离开状态”，禁止只列事件名。高潮应解决核心选择并留下代价，不只提高战力或揭晓答案。

### 4.4 伏笔与信息

建立最小的 `setup -> pressure -> reveal/payoff` 链。每个伏笔标明首次出现、误导、回收位置、回收改变了谁的选择；没有计划回收的神秘信息降级为氛围而非承诺。区分读者知道、视角人物知道、其他人物知道，避免靠全知旁白偷渡因果。

## 5. 固定交付格式

完整版本按 `references/outline-schema.md` 的字段输出。通常采用以下顺序：

1. **版本信息与边界**：模式、版本号、材料范围、事实/改动/推演/假设、非商用或原创化说明。
2. **来源接入**：若来自压缩器，保留 `source_input`、来源状态、回读锚点和压缩风险。
3. **一句话企划与故事承诺**：主角、欲望、阻力、代价、读者最终会看到的变化。
4. **理解快照**：起点、核心问题、关系网、制度/世界压力、未决问题。
5. **用户构思捕获**：`vision_capture`，包括用户原话、画面/情绪/关系/边界和它们对结构的影响。
6. **人物弧与关系变化表**：每人以行为和选择描述，不堆形容词。
7. **宏观结构**：卷/幕/阶段目标、转折、低谷、高潮、结局及每段收口。
8. **章节或场景卡**：按需展开到用户指定粒度；每卡写因果和出口状态。
9. **伏笔、信息与连续性账本**：事实锚点、资源、伤势、时间、承诺、未回收项。
10. **风险与取舍**：篇幅、节奏、角色抢戏、设定膨胀、结局压力、权利/相似性风险。
11. **执行简报**：正文阶段应优先写什么、哪些内容暂不展开、下一次可从哪个节点开始。

### 交付粒度

用户只要“先给个方向”时，交付一页 v0.1，不擅自展开数十章。用户要“完整大纲”时，至少展开到卷/幕和章节卡，并给出回收表。用户要“能直接开写”时，增加前三章/前两个关键场景的场景卡，但仍不把正文伪装成大纲。

## 6. 质量闸门

交付前逐项检查，并用简短结论记录：

- **因果**：每次转折是否由前一选择或可验证压力触发？
- **人物**：每个关键选择是否符合当下信息、欲望和底线？偏离是否有事件与代价支撑？
- **关系**：高潮后至少有一段关系或承诺不可恢复到原状？
- **世界**：规则、组织、资源和物件是否真的改变行动，而不只是装饰？
- **信息**：读者、视角人物和其他人物的知识差是否可追踪？
- **节奏**：连续场景是否重复同一种功能？支线是否有收口节点？
- **维护**：规模能否在用户要求的篇幅内完成？是否留下无主伏笔？
- **边界**：事实、改动、推演没有混淆；参考作品只贡献高层机制；既有 IP 产物定位清楚。

若闸门不通过，不用漂亮措辞掩盖问题。列出最小修复动作，并说明它会连带影响哪些章节或人物。

## 7. 与后续技能的交接

将最终版本视为 `outline_state`。后续正文技能应能够只凭该状态继续工作。至少保留：

- `version`、`mode`、`locked_facts`、`assumptions`
- `source_input`（若有上游压缩状态）与 `vision_capture`（用户的开放构思）
- `timeline_anchor` 与当前所有角色状态
- `open_threads`、`promises`、`payoffs`
- `next_scene_candidates`（至少 2 个，并说明选择差异）
- `change_log`（本轮接受、拒绝和暂缓的修改）

### 从 source_outline_state 接入

当上游压缩技能存在时，使用以下映射，不要把上游摘要当成新的原作事实：

| source_outline_state | outline_state |
| --- | --- |
| `locked_facts` | `locked_facts` |
| `user_constraints` | `user_changes` |
| `inferred_items` | `inferences` |
| `unknowns_and_conflicts` | `open_questions` / 风险 |
| `story_engine` | `story_engine` |
| `timeline_anchor` + `continuity_ledger` | `timeline_anchor` + 连续性账本 |
| `segment_outline` | `segments` |
| `character_states` + `relationship_deltas` | 人物弧与关系表 |
| `open_threads` / `promises` / `payoffs` | `open_threads` / `promises` / `payoffs` |
| `ending_or_last_stable_point` | 起点/分歧点与 `next_scene_candidates` |

同时原样保留以下路由元数据，供后续技能决定是否回读原文：

```yaml
source_input:
  version: "source-v0.1"
  source_scope: "压缩器已覆盖的文件/章节"
  source_status: "complete | unfinished | partial | conflicting"
  mode: "handoff-compress | incremental-merge"
  compression_depth: "quick | standard | deep"
  confidence: "high | medium | low"
  traceability: []
  compression_risks: []
```

接收旧版本时兼容 `state_version` -> `version`、`compression_mode` -> `mode`；生成新 `outline_state` 时统一使用规范字段 `version` 和 `mode`，不要让别名继续扩散。

压缩器的 `compression_risks` 和 `traceability` 必须在大纲风险段保留；它们是提示“哪里值得回读”，不是要求模型擅自补全。

当用户说“继续”“从这里开写”时，先引用当前 `outline_state` 的节点和风险，再进入正文；当用户说“换个方向”时，先指出受影响的变量和连锁改动，再生成新版本。

## 8. 默认行为和禁止事项

- 信息不足时可使用低风险默认，但必须标成假设并允许回滚。
- 不把提问数量当作认真程度；问题少而改变主线更重要。
- 不用设定百科、角色标签或连续反转掩盖没有选择和代价。
- 不在用户只要大纲时擅自写长篇正文；可提供极短的示例句，但标明“示例，不是正文交付”。
- 不把用户未确认的推演写成原作事实，不把参考作品的风格描述写成复制授权。
- 不为求完整而强行填入不服务主线的支线；删除比堆积更接近可完成的长篇。

需要模板或边界细节时，按需读取：

- `references/outline-schema.md`：完整字段、章节卡和 `outline_state` 模板。
- `references/question-bank.md`：按任务模式选择高杠杆问题。
- `references/continuity-ledger.md`：续写/改写的事实、时间、关系、资源和伏笔账本。
